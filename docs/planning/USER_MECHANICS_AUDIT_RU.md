## Сценарии и осторожные выводы

1. **Первая работа.** При пустой базе пользователь открывает создание из счётчика/стола или вкладки проектов, вводит название и выбирает свойства; после успешной записи экран переходит во вкладку «Вяжем». При ошибке записи форма сохраняется и показывает сообщение, успешное создание не заявляется.
2. **Несколько проектов.** При создании нового он становится активным; выбор другого в списке записывает активный ID. Данные счётчиков разделены по project ID. В текущей схеме `project_id` — первичный ключ таблицы counters: несколько независимых счётчиков **внутри одного проекта** не реализованы.
3. **Вязание и исправление.** +1 добавляет событие и меняет значение в одной транзакции. −1 означает распускание и на нуле недоступен; исправление ошибочного нажатия — отдельный undo. Undo ищет последнее ещё не отменённое событие активного проекта и проверяет ожидаемый порядок. Интерфейс отображает подтверждённые данные; контроллер последовательно ставит команды в очередь и фиксирует ID проекта при нажатии.
4. **После перезапуска.** Код вновь открывает локальную БД, а `load()` восстанавливает проект и счётчик; ручного экспорта/импорта и резервного восстановления не обнаружено. Если открыть хранилище не удалось, bootstrap показывает ошибку и кнопку повторного открытия, не предлагая очистку данных.
5. **Пределы модели.** Длина раппорта присутствует как необязательное поле SQL, но не найдены пользовательские действия её настройки или несколько счётчиков. Редактирование метаданных, отметка готовности и прогресс по цели не следует обещать по наличию схемы. Возможная книга узоров/импорт — отдельная будущая работа с проверкой форматов, безопасности и офлайн-доступа, не часть текущей реализации.

- Отдельно запланировать проверку на устройстве: перезапуск/force-stop с синтетическими данными и без удаления пользовательской установки; восстановление после ошибки записи и нехватки места; быстрые нажатия с переключением проектов; крупный системный шрифт, screen reader, контраст и реальные 48 dp на узких экранах. ## Идеи, не утверждены

Деликатное редактирование свойств проекта с защитой от потери изменений; несколько именованных счётчиков для одного проекта; отметка «где остановилась»; осмысленное завершение/архив без удаления данных; безопасный локальный экспорт/импорт после отдельного проектирования. Очередность: сначала согласованный визуальный дизайн и мобильный UX, функциональные модули позже. Никакие изменения не внедрены.
