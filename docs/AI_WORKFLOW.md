# Протокол взаимодействия Work ↔ Макс ↔ Катя

**Статус:** действующий организационный протокол. Не является автоматическим каналом прямого общения между чатами.

## Где находится правда

- Репозиторий: https://github.com/jellyfishkaty-bit/lavka
- Базовая рабочая версия: ветка main; проверять текущий HEAD перед действиями.
- Эксперименты графики: ветка art/pixel-workshop-v2; не считать её готовой к объединению.
- Технический/художественный контекст: [HANDOFF_LATEST.md](handoffs/HANDOFF_LATEST.md).
- Поручение и критерии: соответствующая GitHub Issue **вместе с последними комментариями**.
- Реальное выполнение: коммиты, содержимое файлов, результаты CI, превью и Pull Request; не текст «готово» сам по себе.
- При противоречиях между документами и фактическим кодом — зафиксировать расхождение и выяснить, а не менять молча.

## Один рабочий цикл

1. **Запуск Work:** прочитать AGENTS.md, этот протокол, handoff, нужную Issue, комментарии и открытые PR. Узнать актуальные SHA и что уже сделано.
2. **План:** коротко обозначить, что будет изменено, и отметить блокеры в Issue, если необходимо.
3. **Реализация:** выполнять только одну Issue за раз в нужной ветке. Не делать новых спрайтов, если задача — перенос существующих PNG. Малые коммиты и проверка целостности после каждого.
4. **Контроль перед сдачей:** проверить критерии Issue, перечислить доказательства, отметить, что невозможно проверить без SDK/устройства/архива.
5. **Передача Максу:** открыть PR с точной ссылкой на Issue, приложить ссылки на коммиты, превью, тесты и перечень остатка; оставить PR на ревью.
6. **Получение ревью:** в начале следующего активного цикла перечитать последние комментарии Issue и PR, адресно ответить и внести корректировки. Не удалять замечания.
7. **Решение Кати:** художественное утверждение, принятие рисков и слияние в main — только после явного согласия Кати. В случае несогласия моделей фиксировать альтернативы и аргументы, а не принимать решение за неё.

## Взаимодействие через GitHub

Макс может создавать Issues, комментировать PR, проверять SHA, тесты и состояние репозитория. Настроенная задача ревью Макса проверяет GitHub каждый час, сообщает Кате только о существенном изменении или блокере и может оставить замечания непосредственно в GitHub.

**Ограничение:** чтение комментариев и выполнение новых задач не запускаются в отдельной сессии Work автоматически. Для этого Work должен быть запущен пользователем либо иметь отдельно поддерживаемый и явно настроенный запуск по расписанию/событию. Нельзя писать в отчётах, что два ИИ действуют непрерывно, если механизма запуска нет.

Рабочее правило для Work: когда пользователь открывает/возобновляет сессию, сначала перечитать GitHub и собрать новые замечания, прежде чем работать дальше. Если задача выполнена и комментарии ревьюера ещё не поступили — закончить сессию с PR, а не имитировать бесконечное ожидание.

## Когда звать Катю

- **Обязательно:** нужно художественное утверждение, решение о внешнем виде или изменении утверждённого концепта; требуется изменение/публикация ключей; изменение подписи, applicationId, SQLite-схемы, миграции данных или риск потери данных; разрешение на merge в main; нет доступа к критичным исходникам.
- **Сообщить без лишнего шума:** существенная ошибка, блокирующая разработку; подтверждённая потеря или повреждение файлов; реально завершённый этап с PR и доказательствами.
- **Не тревожить:** отсутствие изменений, новые мелкие коммиты без результата, текущая штатная работа, косметические замечания без потребности в решении.

## Готовность художественной задачи

Нужны: исходные PNG с контрольными суммами, их статус утверждения, корректное размещение в сцене и предпросмотр при фактическом мобильном масштабе (если задача включает интеграцию), сопоставление с утверждённым концептом и прозрачный список неустранённых замечаний. Пробные PNG партии 2Б по умолчанию **не утверждены**.

## Стандарт короткого отчёта Work

- Issue / ветка / текущий commit SHA.
- Что **реально** изменено (пути и коммиты).
- Какие проверки **реально** выполнялись.
- Ссылка на PR и статус ревью.
- Что осталось / блокер / требуется ли решение Кати.

Для задач по графике прилагать реальные изображения/ссылки, не только текстовое описание.
