# Лавка забытых историй · 0.2.1

Flutter + Flame, Android, офлайн SQLite. Художественный этап 2 поверх принятого функционального среза, не полный MVP.

Реализованы создание нескольких проектов, 16 пиксельных иконок и 4 подложки, независимые счётчики, +1/−1 и отмена, атомарные записи SQLite, сохранение активного проекта, лавка из слоёв и переходы между экранами. Дождь ручной. Раздел «Узоры» явно сообщает, что относится к следующему этапу; импорта и фиктивных схем нет.

Новая сцена: 15 независимых PNG, 15 экземпляров предметов, отдельная гавань, дождь, свет и пар. Геометрия и зоны маршрутов общие для Flame и Flutter.

Текущий отчёт: [этап 2](docs/STAGE_02_RU.md), [состав и готовность графики](docs/ASSETS_V02.md). Базовая архитектура хранения: [архитектура](docs/ARCHITECTURE_RU.md). История первого среза: [этап 1](docs/STAGE_01_RU.md).

## Запуск

Проверочная среда: Flutter 3.47.9 stable, Dart 3.13.7; Java 21, Android SDK 36. Android minSdk по шаблону Flutter — 24. Используйте lockfile.

```bash
flutter --disable-analytics
dart --disable-analytics
flutter pub get
flutter analyze
flutter test
flutter run -d <android-device-id>
```

Для проверки нативного SQLite:

```bash
flutter test integration_test/persistence_test.dart -d <android-device-id>
```

Сборка устанавливаемого прототипа:

```bash
./tools/build_debug.sh
```

Скрипт обязательно выполняет `flutter pub get` для генерации регистрации Android-плагинов, затем тесты, сборку и проверку наличия SQLite-плагина в DEX. Один `dart pub get` не заменяет этот шаг. Прямой вызов сборки с `--no-pub` без подготовленных Flutter-метаданных запрещён для поставки.

APK после успешной сборки: `build/app/outputs/flutter-apk/app-debug.apk`. Это debug-подпись для тестирования, не магазинный релиз. Локальные файлы с путями SDK и ключами не входят в поставку.

## Ручная приёмка на Android

1. Создать два проекта с разными иконками и подложками.
2. В первом нажать +1 15 раз, −1 2 раза: должно быть 13. Во втором — 0.
3. Переключить вкладки и проекты, выйти через системную кнопку и открыть снова.
4. Принудительно остановить приложение через настройки Android. Открыть снова: ряд 13, активный проект, иконка и подложка сохранены.
5. В авиарежиме создать новый проект и посчитать ряды.
6. Проверить отмену ошибочного +1 и отличие от распускания.
7. Повторить на узком экране, с большим системным шрифтом и TalkBack.
8. Замерить задержку записи и FPS сцены на реальном телефоне; целевой отклик до 100 мс ещё не подтверждён.

Автотест закрытия/открытия файла не заменяет force-stop, нативную интеграцию и физическое устройство.

## Ресурсы

Подготовка новых спрайтов и архитектуры: `python3 tools/prepare_scene_art.py` (Pillow); исходные PNG и prompts включены в `art_sources`. Иконка запуска: `python3 tools/generate_launcher_icon.py`. Прежние проектные значки и старый технический арт воспроизводятся через `python3 tools/generate_art.py`. Иллюстрация из ТЗ не используется как готовый интерфейс. Размеры, палитра, z-порядок, хитбоксы и ограничения описаны в архитектуре. В поставке локальные кириллические шрифты PT Sans и Press Start 2P с OFL. Зависимости сохраняют собственные лицензии; перед публикацией нужен полный аудит.

Пока нет резервного копирования. Не используйте прототип как единственное место хранения важного прогресса. Он сохраняет данные при обычных перезапусках, но переустановка/очистка данных может их удалить.
